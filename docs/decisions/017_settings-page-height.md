## 017. 設定画面は文言の圧縮と節の統合・並び替えで縮め、折りたたみは説明文だけにする

- 日付: 2026-09-08
- 対象: `src/SettingsView.tsx`、`src/styles.css`（`.settings-group > p`・`.settings-help`）、`tests/settings-view.test.tsx`

### 背景

設定が増え、iPhone（390×844）で 2,748px・3.3 画面分になっていた（2026-09-08 ユーザー要望「スクロールが増えてきたので高さを縮める検討を」）。
実測すると高さの 31%（840px）が灰色の説明文で、見出し 7 本の余白と、`p` の既定マージン（flex の gap に上下 1em が足される）も効いていた。

### 決定

1. **節を使う頻度順に並べる**: 学習 → 表示と動作 → バックアップ → GitHub トークン → メンテナンス。以前はトークンが先頭で、毎回 1 画面ぶん飛ばしていた
2. **節を統合して見出しを 5 本にする**: 「答えの検索」＋「アニメーション」→「表示と動作」、「学習進捗のバックアップ」＋「GitHub へのバックアップ」→「バックアップ」。「GitHub トークン（編集用）」はバックアップにも使うので「GitHub トークン」に改名
3. **説明文は各 1 行**。長い説明は節の末尾の「説明を見る」（`<details>`）に畳む（ユーザー了承済み）。「実際のデッキ数を入れる」（2026-08 決定）は 1 行に縮めて表に残す
4. **設定カード内の `p` はマージン 0**。間隔は flex の gap（12px）だけで取る
5. 結果: 2,748px → 1,992px（3.3 画面 → 2.4 画面）。ボタン高さ 38px の下限は触らない

### 比較した代替案

- 却下（保留）: 使用頻度の低い節を既定で畳む — 1.6 画面まで縮むが、毎回タップが増える。まず本案で様子を見て、まだ長ければ次に入れる（ユーザー選択）
- 却下: iOS の設定アプリのようなサブページ化 — 一覧は 1 画面に収まるが全設定が 1 階層深くなる。5 節では見合わない
- 却下: ボタン・入力欄を低くする — 38px の下限は 2026-08-26 に決めた
- 採用: 上記の決定

### 影響範囲

- 設定の項目・保存先・挙動は変えていない。並びと文言だけ
- 「説明を見る」は `summary` の `display` を変えると開閉の三角が消えるので、タップ領域は padding で 38px にした

### 検証

- `tests/settings-view.test.tsx`（新設 3 件）: 見出しの並び、`details` が 4 つとも閉じている・PAT の説明が畳みの中、新規カードの説明が 1 行でデッキ数入り・無制限で文言が変わる、ブラウザ選択が保存される。全 315 件通過
- preview + headless Chromium（390px）: 高さ 1,992px、横スクロールなし、summary の高さ 38px、タップで開く
- 兆候: 説明を畳んでから「なぜこの設定があるのか」を忘れる。そのときは summary の文言を「〜とは」など内容に寄せる
