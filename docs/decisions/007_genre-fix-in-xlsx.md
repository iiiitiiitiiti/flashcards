## 007. ジャンル誤りは xlsx 側で直し、進捗の引き継ぎは諦める。列は名前で探す

- 日付: 2026-09-04
- 対象: `scripts/import-quiz-xlsx.py`（列の探し方・改行）、`scripts/sync-decks.mjs`（Windows 対応）、
  クイズ.xlsx「ノンジャンルクイズ」H〜I 列（大・小ジャンル）の一括修正

### 背景

生き物デッキに「丸腰」（言葉の語源問題）が入っているなど、大ジャンルが明らかに違うカードがあった。
調べると単発ではなく、通し番号（U 列「No」）27825〜28300 あたりの約470行に無関係な大ジャンルが付いていた。
割合は2〜3割。誤りは3系統の受け皿に集中していた。「元々は〜」の語源問題が 生き物/植物･果物、
国連・銀行・人物が 地理/日本-その他、雑多な問題が 理系/天文学。他の区間をサンプル点検した範囲では誤りゼロ。

同時に、xlsx に列が挿入されて「No」が Q 列から U 列へ動いていた。固定位置（16）で読む取り込みスクリプトを
そのまま走らせると**全カードの id がハッシュ id に変わり、学習進捗が全部孤児になる**状態だった
（`decks:sync` の削除ガードで止まるが、生成そのものが壊れる）。

### 決定

1. **修正は xlsx 側に入れ、デッキ JSON は再生成する。** `decks/README.md` の規約どおり `quiz-*` は手で触らない
2. 125 行の大・小ジャンルを xlwings 経由で書き戻す。書く前に「U 列の通し番号」と「現在の大・小」が一致することを
   全行で照合し、1件でもずれていれば書かない。書く前に `~/.claude/quiz-backups/` へバックアップ
3. ジャンルが変わったカードはデッキが移り、**学習進捗は引き継がない**（進捗は (デッキ id, カード id) で持つ仕様のまま）。
   `decks:sync` は `--allow-removals` で通す
4. 取り込みスクリプトは**列をヘッダー名で探す**。見つからない・複数ある場合は止める。JSON は `newline="\n"` で LF 固定
5. 修正案の作成は、区間を4分割して Sonnet サブエージェントに「明らかな誤りだけ」を拾わせ、体系（`quiz_io genres`）に
   ある名前だけを許す機械検査を通したうえで、境界事例（県の獣→愛媛県 など）は人手で落とした

### 比較した代替案

- 却下: デッキ JSON の tags / 所属デッキを直接直す — 次の `decks:sync` で xlsx の内容に上書きされて元に戻る。正本は xlsx。
- 却下: ジャンル変更時に旧デッキの進捗レコードを新デッキへ移す（進捗マイグレーション） — 進捗の鍵は (deckId, cardId)。
  アプリ側に「このカードは元 quiz-ikimono の 27867 だった」という対応表を持ち込む必要がある。
  125枚（大半が未学習の新しめの問題）のために永続的な複雑さを足す価値がない。
  必要になったらバックアップ JSON の deckId 書き換えで個別に救える
- 却下: openpyxl で xlsx を保存する — 入力規則（データの検証）が壊れる。quiz_io の作法どおり xlwings（実 Excel）で書く
- 却下: 全 29,775 行を LLM で再分類する — 誤りは特定区間に集中しており、正しい区間まで揺らす危険の方が大きい。
  サンプル点検で「他区間は誤りゼロ」を確かめたうえで区間に限った
- 却下: 取り込みスクリプトの固定位置を 16 → 20 に書き換えるだけ — 次に列が挿入されたときまた同じ事故になる
- 採用: 上記の決定

### 影響範囲

- `decks/quiz-*.json`: 15 デッキで 124 枚が移動（2026-09-04 の再生成コミット）
- 修正一覧: `~/.claude/quiz-backups/genre-fixes_20260904.tsv`（serial・行・旧→新ジャンル・理由）。xlsx のバックアップも同フォルダ
- `decks/README.md` の「ジャンルを変えると学習進捗は引き継がれない」がこの判断の根拠になっている

### 検証

- 取り込みスクリプトの修正後、直す前の xlsx で `decks:sync --dry-run` を通した。HEAD との差分は「8/26 以降に追加された
  212 枚」と「xlsx 側でジャンルを直した1枚の移動」だけで、id の振り直しが起きていないことを確認した
- 書き戻し前の照合で、サブエージェントが書き誤った行番号3件・現在値1件を検出して弾けた（照合を入れた効果）
- 書き戻し後に openpyxl で読み直し、27867（丸腰）が 言葉/流行語･日常･方言 になっていることなどを確認。再生成・検証・push まで成功
- 同じ区間で別の誤りが見つかったら、この判断ではなく修正案の網羅性の問題。区間外で塊が見つかったら「他区間は誤りゼロ」の前提が崩れる
