## 019. 「間違えたカードだけもう一度」は、結果画面から新しいセッションを開き直して出す

- 日付: 2026-10-09
- 対象: `src/StudyResult.tsx`（ボタン）、`src/StudyView.tsx`（`retryKeys`・`onRetryMissed`・`missedKeys`）、`src/App.tsx`（`View.study.retryKeys`・`startStudy`）、
  `src/styles.css`（`.result-retry`）

### 決定

1. 結果画面に「間違えた N 枚をもう一度」（早押しは「不正解の N 枚をもう一度」）を出す。N はこのセッションで「もう一度」（rating 1）を付けたカードの数。0 枚なら出さない
2. 押すと App の `startStudy` を同じ設定（デッキ・モード・並び・タグ・範囲）のまま `retryKeys` 付きで呼び、**新しい sessionId でリマウントした別セッション**として出す
3. 数えるのは `undoStack` の rating 1 を重複なしで、最初に間違えた順。取り消した評価・非表示や移動で外したカードは `undoStack` に残らないので自然に入らない
4. やり直しでも評価は通常どおり FSRS へ保存する（011 の決定5と同じく、早期復習の影響は許容する）
5. `retryKeys` は期限・枚数・タグ・範囲を見ず、渡したカードを全部出す（枚数で切らない）。見つからないキー（削除・非表示・移動）は飛ばし、全部見つからなければ「もう一度出せるカードはありません」を出す
6. 中断して結果画面へ来たときもボタンを出す。押すと残りのキューは出さずに終わるので、文言を「残りをやめて、〜をもう一度」にする
7. やり直しセッションの結果画面から「つづける」を押すと `retryKeys` を落とし、通常のセッションへ戻す。やり直しでまた間違えれば、そこからもう一度やり直せる

### 背景

セッションの最後に、間違えたカードだけをその場で回したい。これまでは「つづける」で次の期限カードへ進むか、苦手ドリル（011）を開き直すしかなかった。
苦手ドリルは進捗全体から判定するので、「今回のセッションで間違えた分」とは一致しない。

### 比較した代替案

| 案 | 却下理由 |
|---|---|
| B: 同じ StudyView のマウントのままキューだけ差し替える | 初期化が `useMemo(initialQueue)` と `useState(initial)` に依存している。差し替えると `initialQueue.length === 0` の分岐や完了判定の `useEffect` と噛み合わず、状態の不整合を個別に潰す必要がある |
| やり直しの評価を保存しない（表示だけ） | 定着率・評価ログ・統計を別扱いにする設計が要る。011 で同じ理由から却下した |
| 苦手ドリル（011）の範囲に「今回のセッション」を足す | 開始シートを経由させると、結果画面から1タップで始められない |

採用: 案A（fable-advisor との壁打ちで推薦）

### 制約

- リマウントするので、やり直しセッションの中から前のセッションの評価は取り消せない（取り消せるのは結果画面にいる間だけ）

### 影響範囲

- `startStudy` の末尾に引数 `retryKeys`（省略時 null）が増えた。既存の呼び出しは変わらない
- `buildStudyQueue` は通らない。`retryKeys` があるときは `StudyView` の `initialQueue` で直接組む（新規扱いにしない）

### 検証

- `npm run lint`・`npm test`（26 ファイル 320 件）・`npm run build` すべて成功
- `tests/study-view.test.tsx` に4件
  - 早押しで ×○×○×○ と答えると「不正解の 2 枚をもう一度」が出て、最初に間違えた順のキーで呼ばれる
  - 中断すると「残りをやめて、」が付く。取り消して0枚になるとボタンが消える
  - `retryKeys` の順に出て、枚数（sessionSize 1）で切られず、消えたカードは飛ばす。間違えなければボタンは出ない
  - 見つからないキーだけなら「もう一度出せるカードはありません」
- preview + headless Chrome（390×844）: 早押しの1枚目を不正解にして中断すると「残りをやめて、不正解の 1 枚をもう一度」が出る。押すとそのカードだけの「残り 1 枚」のセッションになる
