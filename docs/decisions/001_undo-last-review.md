## 001. 直前の評価の取り消しを、セッション内スタック＋同一トランザクションで実装する

- 日付: 2026-08-27
- 対象: `src/db.ts`（`undoReview`）、`src/StudyView.tsx`、`src/StudyResult.tsx`

### 背景

逆向きにスワイプして意図しない評価が付いてしまう事故がある。評価は**進捗（`cardProgress`）と評価ログ（`reviewLog`）の2箇所**へ同時に書いており、
どちらか片方だけ戻すと、統計（めくったカード・プレイ時間）と学習スケジュールが食い違う。
また FSRS の評価は「1つ前の状態」を保持していないため、取り消すには**評価前のレコードを別に控える**必要がある。

### 決定

- 評価が成功するたびに、**評価前の進捗レコード・`reviewId`・rating・経過時間**をセッション内のスタックへ積む
- 取り消しは `undoReview` が**進捗とログを同一トランザクション**で戻す。初回評価だったカードは進捗レコードごと削除する
- 戻したカードは**答えを出したまま**キューの先頭へ返し、**経過時間を引き継ぐ**
- 取り消しは**カードの上の操作行の左端**と、**リザルト画面**の2箇所から行える

### 比較した代替案

- 却下: **進捗に「1つ前」を持たせて DB へ保存する** — スキーマが増えるうえ、取り消しは学習中しか使わない。セッションを離れたら取り消せなくてよい（離れた時点で本人の意思とみなせる）ので、永続化する必要がない
- 却下: **取り消しを1回だけにする** — スタックにしても状態は1本の配列で、実装量はほぼ変わらない。連続で間違えることは普通にある
- 却下: **戻したカードを未表示（問題文だけ）に戻す** — 目的は「付け直すこと」で、読み直させる必要がない。早押しでも答えを出した状態で戻す
- 却下: **戻したときに計測をやり直す** — 戻した直後に右スワイプすると経過数秒＝「簡単」に倒れ、**間違いを直すつもりが別の間違いになる**。取り消し前の経過時間を `shownAt` に埋め戻す
- 却下: **リザルト画面には置かない（要望どおりカードの上だけ）** — 最後の1枚を誤スワイプするとリザルトへ移り、カード上のボタンでは戻せない。**誤スワイプが最も起きる場面が行き止まりになる**ので、要望の配置は変えずに出口だけ足した
- 採用: 上記の「決定」

### 影響範囲

- 統計（`src/stats.ts`）は `reviewLog` を数えるので、ログを消し忘れると「めくったカード」「プレイ時間」がずれる
- リザルトの定着率・フェーズ表示は `progressRef` を見るため、取り消し時に必ず同期する
- 「もう一度」（rating=1）はキュー末尾へ再出題を足すので、取り消しでは**その1枚も取り除く**（`withoutLastAppearance`）
- 控えはセッション内のみ。`key={sessionId}` で `StudyView` が作り直されると消える

### 検証

- 「難しい」で評価 → 取り消し → 元のカード・残り枚数・DB がすべて評価前へ戻る（新規カードは進捗ごと消える）
- 左スワイプ（もう一度）の取り消しで、末尾へ足した再出題も消えて枚数が合う
- 2回評価 → 2回取り消しで逆順に戻る
- 72秒放置して右スワイプ → 取り消し → 即スワイプでも 73秒扱い（引き継がなければ約1秒＝「簡単」）
- 3連打で消えるのは1件だけ
- ログ削除だけを失敗させると **DB は一切変わらず**、エラーを表示。復旧後に押し直すと成功

**判断が間違いだったとわかる条件**: 統計の「めくったカード」が実際より多い／取り消したカードが翌日以降も出ない（進捗が戻っていない）／取り消し直後の評価が意図せず「簡単」になる。
