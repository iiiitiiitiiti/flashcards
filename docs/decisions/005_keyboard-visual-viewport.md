## 005. キーボードで画面が持ち上がるのを、入力欄を画面上部へ置いて防ぐ

- 日付: 2026-08-27
- 対象: `src/viewport.ts`（新規）、`src/StudyView.tsx`（メモのダイアログ）、`src/styles.css`

### 背景

カードのメモを開くとキーボードが出て、**後ろの学習画面ごと上へずれる**という指摘。

iOS Safari はキーボードが出ても**レイアウトの高さを変えない**。代わりに、入力欄が隠れるなら
画面全体をスクロールして持ち上げる。ダイアログは `position: fixed; inset: 0` で全画面のままなので、
入力欄が下半分にあると必ず持ち上げが起きる。

### 決定

**メモを `<dialog>` の `showModal()` で出し、画面上部へ置く。**

決め手は**配置**の方。iOS が画面を持ち上げるのは「入力欄がキーボードに隠れる位置にあるから」なので、
上部に置いて隠れなくすれば持ち上げる理由が無くなる。メモは下寄せのシートだったため、
textarea がちょうどキーボードの下に来ていた。

`<dialog>` は上位レイヤーへ載るので親の `overflow` や `z-index` の影響を受けず、背景が不活性になる。
Esc は `onCancel` で受けて `closeNote()` へ流す。

`visualViewport` の位置（`--viewport-top`）は**保険として上端へ足すだけ**に格下げした。

- jsdom は `showModal` / `close` を実装していないので、無い側は `open` 属性で代用する
- **フックは早期 return より前で呼ぶ。** `dialogs` の定義位置は結果画面の early return より後ろなので、
  そこで呼ぶとリザルト表示時にフック数が変わって壊れる（コンポーネントテストが実際に捕まえた）

#### 初版（2026-08-27 午前）の誤り

最初は「`visualViewport` の高さをダイアログの背景に当てて見えている領域へ縮める」だけで直ると考えたが、
**実機で直らなかった**。縮めても中のシートは下寄せのままで、入力欄はキーボードの位置に残る。
iOS が持ち上げるかどうかを決めるのは領域の大きさではなく**入力欄の位置**だった。

### 比較した代替案

- 却下: **`visualViewport` の高さに背景を合わせるだけ**（初版）— **実機で直らなかった**。
  領域を縮めても入力欄の位置は変わらないので、持ち上げは起きる
- 却下: **`<dialog>` へ変えるだけ** — 上位レイヤー・不活性化は得られるが、
  **持ち上げの原因は重ね順ではないので単体では止まらない**。配置と併せて初めて効く
- 却下: **`interactive-widget=resizes-content` を viewport メタに足す** — 宣言1行で済むが、
  iOS Safari が対応しているか確認できなかった。**確認できないものに挙動を委ねない**
- 却下: **`body` を `position: fixed` にしてスクロール自体を殺す** — 効くが、学習画面のスクロール
  （長い問題文のカード内スクロール）まで巻き添えになる。副作用が読めない
- 採用: **`<dialog>` ＋ 画面上部への配置**（＋保険としての `--viewport-top`）

### 影響範囲

- **メモのダイアログだけ**に当てている。非表示の確認・学習開始シートには入力欄が無い
- `DeckDetailView` のカード編集にも入力欄があるが、そちらは今回触っていない。同じ症状が出るなら同じフックを当てる
- `visualViewport` が無い環境（古いブラウザ、テストの jsdom）では従来どおり全画面

### 検証

preview + Playwright 390×844。

- 要素が本当に `<DIALOG>` で、`open` が立ち、`position: fixed`
- ダイアログの上端 12px、**入力欄の下端 180px**。iPhone のキーボードは画面の約4割を占めるので、
  844px なら上端はおよそ 490px。入力欄はその **310px 上**にあり、隠れる余地がない
- メモを開いた直後に `textarea` へフォーカスが入っている
- コンポーネントテストを2件追加（開く→保存、空にすると消す）。**変異でも確認済み**：
  `showModal` の呼び出しを消すと「開くと入力欄が出て、とじると保存される」だけが落ちる
- 173件 pass

**実機 iOS では未検証。** Playwright は Chromium で、本物のソフトキーボードは再現できない。
初版はこの状態で「直った」と報告して外したので、今回は**確認できていないと明示して引き渡す**。

**判断が間違いだったとわかる条件**: iPhone でメモを開いたとき、まだ背景の学習画面がずれる。
または、キーボードを閉じたあとにダイアログの高さが戻らない。

### 影響範囲（追記）

- `DeckDetailView` のカード編集・CSV 取込にも入力欄がある。同じ症状が出るなら同じ形（`<dialog>` ＋ 上部配置）にする
- 非表示の確認と学習開始シートは入力欄が無いので、従来の `.sheet-backdrop` のまま
