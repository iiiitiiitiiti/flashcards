## 012. 「まとめて学習」は全デッキの復習を1セッションにし、学習画面は (デッキ id, カード id) の複合キーで動かす

- 日付: 2026-09-04
- 対象: `src/srs.ts`（`buildStudyItems`・`progressKey`）、`src/StudyView.tsx`（`decks` / `title` / `moveTargetsFor` / `onHide(deckId, cardId)`）、
  `src/StudyResult.tsx`（`percent: number | null`・`scopeLabel`・一覧のデッキ名）、`src/App.tsx`（`ALL_DECKS`・`View.study.deckIds`・ホームのボタン）、`src/styles.css`

### 背景

デッキをまたいで出題したい（2026-09-04 ユーザー要望）。「★★★だけ」「出題済みだけ」のように全デッキ共通のタグで絞って回す使い方と、
毎日の復習を、デッキを1つずつ開かずにすませる使い方の2つ。ユーザーは対象を「期限が来た復習」と「タグで絞る」に決め、新規カードと苦手の横断は今回外した。

### 決定

1. **ホーム上部に「まとめて学習」**。押すと既存の開始シートが全デッキ対象で開く（モード・出題順・枚数・タグ）。範囲（苦手）の切替は出さない。
   ボタンの横には「全デッキで復習できるのは N 枚」を出す（統計と同じ visibleDeck 基準の合計）
2. **新規カードは出さない。** 期限が来た復習だけを全デッキ通しで期限の早い順に出す（ランダム指定なら全体をシャッフル）
3. **タグ候補は「いま復習できるカードに付いているタグ」だけ。** 全デッキの和集合（185 種）を並べず、選んだ瞬間に 0 枚になる候補も出さない
4. 学習画面 `StudyView` は **`decks: Deck[]`** を受け、進捗・メモ・キュー操作（取り消し・編集後の差し替え・移動・非表示）を
   **`progressKey(deckId, cardId)`** で扱う。開いたダイアログ（メモ・非表示・編集）は開いた時点の deckId を state に持つ
5. またぐときはカードの上に**デッキ名のチップ**、結果一覧にもデッキ名。見出しは「まとめて学習」
6. 結果画面の**定着率ゲージは出さない**（`percent: null`）。分母が全カード（3 万枚）になり、良いセッションの直後でも 0% 近くになって意味を失う。
   コメントは「今回のぶんで N フェーズ進みました。デッキごとの定着率はホームで確認できます」
7. 開始シートで読んだ進捗を開始時に渡し、全デッキぶん（`readAllProgress`）を2回読まない。結果画面の「つづける」判定は
   `useMemo`（評価・取り消しのたびに再計算）にし、描画ごとの全カード走査を避ける
8. `buildStudyQueue`（1デッキ）はそのまま残し、`buildStudyItems` はデッキごとにそれを呼んで並べ直す。苦手・新規枠・タグの規則は1か所（`buildStudyQueue`）にある

### 比較した代替案

- 却下: 仮想デッキ（全カードを1つの Deck に詰め、id にデッキ id を埋め込む） — 進捗の保存で id を分解する必要があり、編集フォームや GitHub 書き込みへ偽 id が漏れる
- 却下: 下ナビへ「学習」タブを足す — 4タブになり、デッキ一覧からの導線と重複。ユーザーがホーム上部を選択
- 却下: またぐときも新規を出す — 「デッキごと / 全デッキ合計」の新規上限との整合が要る。ユーザー了承で今回は外す
- 却下: タグ候補を「2デッキ以上に現れるタグ」にする（v1 案） — 現データでは ★ と出題済みだけになって都合よく見えるが、1デッキに 500 枚ある有用なタグを落とし、
  2デッキに1枚ずつある打ち間違いタグを通す。Opus レビューの指摘で「復習できるカードに付いているタグ」へ
- 却下: 横断の定着率を「セッションに含めた全デッキのカード合計」で出す（v1 案） — 分母が 3 万枚。ゲージとコメントは常に最低段になる
- 却下: `moveTargets: Deck[]` を `allDecks` に替えて内部で計算する（v1 案） — 既存テストが移動先を注入している。`isWritableDeck` の絞りでテストの相手が候補から落ちて静かに壊れる。
  `moveTargetsFor(deckId)` の関数 props にした
- 却下: またぐときのタグを前回の選択として覚える — 候補が進捗で毎回変わるので、覚えた値が無いことが多い。常に「全タグ」で開く
- 採用: 上記の決定

### 影響範囲

- `StudyView` の props が変わった（`deck` → `decks` + `title`、`moveTargets` → `moveTargetsFor`、`onHide` に deckId、`initialNotes` の鍵は `progressKey`）。呼び出しは App とテストだけ
- `View.study` は `deckIds: string[]`。学習中に消えたデッキは外し、全部消えたらホームへ落ちる
- ホームに `.study-all`、カードに `.chip-deck`、結果一覧に `.result-deck` を追加
- またぐときの `usedNewCardsToday` は無関係（新規を出さない）

### 検証

- `tests/srs.test.ts`（6 件）: 全デッキ通しの期限順／同じ cardId が別デッキにあっても混ざらない／タグ／`includeFresh` の有無／1デッキで `buildStudyQueue` と同じ並び／苦手の横断並び／`progressKey`
- `tests/study-view.test.tsx`（4 件）: 期限順・デッキ名チップ・進捗がそれぞれの deckId で保存される（片方は未保存のまま）／同じ id の取り消しが別デッキの再出題を消さない／
  メモと非表示がそのカードのデッキ id で保存される／結果画面はゲージ無し・デッキ名あり・「全デッキで今日出せるカードは終わりました」。既存 27 件はハーネス更新で全部通る
- preview + Chrome: ホームに「まとめて学習」が出て、復習 0 枚なら無効＋「いま復習できるカードはありません」。実データでの一連の流れ（シート → 学習 → 結果）は iPhone で確認する（Mac 側の引き継ぎ）
- 兆候: 全デッキの進捗が数万件になって「まとめて学習」を開くのが遅い（`readAllProgress` の1回読み。索引や件数の間引きが要る）、
  またぐときに「この問題はどのデッキか」で迷う声が出る（チップの見せ方を強める）
