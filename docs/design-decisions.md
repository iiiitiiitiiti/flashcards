# Design Decisions

UI に関する確定済みの設計判断。変更するときはここを更新する。

## ライトテーマ固定（2026-08-26 ユーザー決定）

- OS のダークモードには追従せず、常にライト配色で表示する（`color-scheme: light`、`prefers-color-scheme: dark` の上書きブロックは削除）
- `theme-color` メタタグも 1 枚（`#f6f6f4` = `--color-bg`）に統一。以前の light 用の値 `#f5f6f8` は背景色と一致していなかったので揃えた
- 配色トークン自体は据え置き。ダークを再開するなら `:root` のトークンだけを上書きする形に戻す

## ビジュアル言語（2026-08-10、Newmonic https://newmonic.baton8.com を参考に採用）

- ティール基調 + 温かみのあるオフホワイト背景（#f6f6f4）。プライマリは #2e7382（Newmonic の #489FB2 は白文字とのコントラスト 3.05 で不採用。当プロジェクトの 4.5:1 基準を満たす濃ティールに調整）
- **Q/A の色分け**: 一覧・学習画面とも「Q」=ティール、「A」=赤（#c53f35、ダークは #ef8b80）。答えは常に赤文字
- デッキ詳細の各カードに元順の番号とフェーズバッジ（= FSRS reps。定着（state=Review）は塗りつぶし）
- ホームのデッキカードに定着率ドーナツゲージ（定着カード数 / 全カード数、conic-gradient 製）
- セクション見出しはティール縦棒 + 太字。アプリタイトルはティール + letter-spacing 0.08em
- ボタン角丸 8px（Newmonic の角丸小さめの印象を反映しつつタップターゲット 44px は維持）
- 評価4択 + 間隔表示は維持（Newmonic は2択だが、SRS の判断材料として4択を優先する既決定）

- 学習画面の主要操作（答えを表示・4評価）は画面下部固定（HIG: Reachability。片手操作の親指ゾーンに置く）。カード本文は中央寄せ・24px/22px でコンテンツ優先（Deference）
- 評価ボタンには ts-fsrs の `repeat()` による次回間隔の目安（分/時間/日/か月/年）を常時表示する（評価の判断材料。Anki 互換の慣習）
- セッション進捗はヘッダー直下の進捗バーで表示。「もう一度」の再出題でバーが一時的に戻るのは仕様（正直な残量表示を優先）
- カラーは CSS 変数トークンで一元管理し、`prefers-color-scheme: dark` に対応。theme-color メタタグも light/dark の2枚で切替
- 全テキストはコントラスト比 4.5:1 以上を維持する（WCAG SC 1.4.3）。「難しい」ボタンは #b07a1f → #8a5f14 に変更済み（3.72→5.6）。値を変えるときは scratchpad の ui-audit スクリプト相当で実測してから
- ボタンは最小 44px 高（HIG タップターゲット）。学習画面の主要ボタンは 56px
- バッジ・タグはチップ表示（復習=赤系 / 新規=青系 / 完了=緑系。色+テキストの併用で色覚に依存しない）
- 状態切替（カードめくり）は state 即時反映、CSS transition は装飾のみ。`transitionend` にロジックを載せない（iOS「視差効果を減らす」対策）。`prefers-reduced-motion` では進捗バーの transition を無効化

## 学習画面の操作（2026-08-10 ユーザー指定）

- 学習中はページの上下スクロールを禁止する（body に study-lock クラス、overscroll-behavior: none）。カード本文が収まらない場合のみカード内部でスクロール
- カード枠は操作エリアを除く画面の縦いっぱいに広げる。中央寄せは auto マージン方式（justify-content: center は overflow 時に先頭が切れるため使わない）
- カードのタップは表⇄裏のトグル（答えを開いた後もタップで問題面に戻れる）
- カードの表裏は 3D 反転アニメーション（rotateY・0.4s）、次カードは右からの入場アニメーション（0.28s、key 再マウントで発火）。両面を常に DOM に置き backface-visibility で切替、非表示面は aria-hidden。状態切替は即時で、アニメはロジックに関与しない。**OS の `prefers-reduced-motion` は参照しない**（2026-08-10 ユーザー決定。Newmonic 等の一般アプリと同じく既定でフル再生）。動きを減らすのはアプリ内設定（設定画面 → アニメーション、`data-motion="crossfade"`）で、回転・移動をクロスフェードへ置き換える。zoo-aquarium-log の「既定は表示・設定でオフ」と同じ方針
- 学習カードは左右スワイプでも評価できる（左=もう一度、右=普通。答え表示中のみ有効）。「難しい」を左に割り当てないのは、FSRS では難しい(2)も合格扱いで間隔が延びるため「覚えてない」の意図とずれるから。難しい・簡単はボタン専用。スワイプ中はカードが指に追従し評価バッジ（次回間隔つき）を表示、閾値80px未満は復帰。縦スクロールとの競合は方向判定（縦優勢なら譲る）で回避

## 学習セッションの開始と評価（2026-08-26 ユーザー要望）

- ホームの「学習する」は即開始ではなく**開始シート**を挟む。モード（通常 / 早押し）と枚数（5・10・20・30）を選んでから始め、選択は localStorage に覚えて次回の既定にする
- 枚数は `buildStudyQueue` の結果（復習 → 新規の順）を先頭から切り取るセッション上限。1日の新規上限 `NEW_CARDS_PER_DAY` とは別の概念で、「もう一度」の再出題はこの上限に含めない
- 答え表示後の**ボタンは2つ**（「難しい」= Hard、「わかった」= Good）。4段階を全部ボタンに出すのはやめ、細かい振り分けはスワイプに寄せた
- **右スワイプは経過時間で自動評価**する。**問題が表示されてから**スワイプするまでが 5秒未満=簡単 / 10秒未満=普通 / 20秒未満=難しい / それ以上=もう一度（既定値。設定画面で変更でき、`normalizeRatingThresholds` が昇順・1〜600秒へ整える）。スワイプ中のバッジには判定結果と次回間隔を出す
- 計測の起点は**問題の表示**（2026-08-26 ユーザー訂正。当初は答えの表示を起点にしていた）。答えを見ている時間も込みで測るため、既定の境界は答え表示起点のとき想定していた 2/5/10 秒から 5/10/20 秒へ引き上げた。答えを表示したあと問題面に戻して見直しても起点は変わらない
- **左スワイプは「もう一度」固定**のまま。覚えていないと即断したときに秒数で揺れると困るため
- 判定境界は使いながら調整する前提の仮置き。閾値は `DEFAULT_RATING_THRESHOLDS` が正本

## 早押しクイズモード（2026-08-26 ユーザー要望）

- 問題文の1文字ずつ送りは**書記素単位**で切る（`splitGraphemes`）。`Array.from` だとサロゲートペアは割れないが ZWJ 絵文字（👨‍👩‍👧‍👦）や結合文字が分解される。`Intl.Segmenter` が無い環境ではコードポイント単位へフォールバック
- 問題文を1文字ずつ送り、**「押す」（またはタップ）で読み上げが止まるだけ**。答えは出さず、**もう一度タップ（または「答えを表示」）で答えを開く**（2026-08-26 ユーザー指定。押した直後に答えが出ると、思い出す時間が取れないため）。文字送りは `Array.from` で分割するのでサロゲートペアでも壊れない
- 速度は1文字あたり 速い70ms / 普通120ms / ゆっくり180ms。設定画面で選び、セッション開始時の値をそのセッション中は固定する
- 正誤は**自己申告**（「正解」= Good / 「不正解」= もう一度）。表記ゆれの誤判定を避けるためテキスト入力での自動判定は採らなかった
- 結果は通常学習と**同じ SRS 進捗に反映**する（進捗を2系統に分けない）。押した文字数はフッターに表示するだけで、評価には使わない
- 早押しでも**スワイプ評価を使える**（2026-08-26 ユーザー指摘で追加）。左=不正解 / 右=正解 で、ボタンと同じ2択に対応させる。通常学習と同じく答えを表示するまでスワイプは効かないので、読み上げ中に誤爆しない
- 早押しの経過秒数による自動評価はしない。速さは「何文字目で押したか」で表れるため、時間で測ると二重になる

## ピンチズームの無効化（2026-08-26 ユーザー指定）

- viewport メタに `maximum-scale=1.0, user-scalable=no` を付け、`body { touch-action: manipulation }` でダブルタップ拡大も止める
- iOS Safari は `user-scalable=no` を無視するため、`main.tsx` で `gesturestart` / `gesturechange` / `gestureend` を `preventDefault` して塞ぐ（WebKit 固有イベント）

## カード一覧・ヘッダー（2026-08-26 ユーザー要望）

- カード一覧は **30枚ごとのページネーション**。ページャは一覧の上下に置き、先頭・末尾・現在の前後を残して「…」で省略する（`buildPageItems`）。検索・タグを変えたら1ページ目へ戻し、ページ数が減ったら `clampPage` で範囲内へ収める
- `.app-header` は `position: sticky` で追従させる。`.app` の左右パディングぶん外へ広げて背景を全幅にする
- デッキ詳細・設定の戻るボタンは**左端の丸いアイコン**（○ の中に ←、44px）。テキストの「戻る」はやめた
- 設定のチェックボックスは横並び。縦積みになっていたのは `.settings-group label`（詳細度 0,1,1）が `.checkbox-label`（0,1,0）に勝っていたためで、`.settings-group .checkbox-label` を足して解消した

## 数万問のデッキへの対応（2026-08-26、クイズ.xlsx の29,781問を導入）

- 全問を1ファイルにすると 9.3MB になるため、**大ジャンル別の16デッキ**へ分けた（最大は quiz-seikatsu の 1.1MB / 3325問）。ジャンル別に学習でき、取得も分散する
- `refreshSnapshot` は**中身が変わったデッキだけ取り直す**。以前は毎起動で全デッキの raw を取り直していたので、10MB 級だと成立しなかった。実測: 初回 2.9秒 → 2回目 0.6秒・raw リクエスト0件
  - 判定は**ファイルごとの blob SHA**（ツリーAPI が返す `sha`）。最初はリポジトリの最新コミット SHA で見ていたが、それだとソースを1行直しただけでも全16デッキ（9.8MB）を取り直していた（2026-08-26、Codex レビューを受けて変更）
  - `commitSha` は raw URL の固定とスナップショットの整合性のために残す。キャッシュ再利用時も最新コミットへ更新する
  - `blobSha` を持たない旧キャッシュは一度だけ取り直す（`DeckCacheEntry.blobSha` は省略可）。削除・追加の判定は従来どおり一覧（`listing.decks`）を正とするので、リネームは新 id で取得され `validateDeck` で中身の id も検証される
- 1日の新規カード枚数を設定可能にした（10/20/50/100/無制限）。29,781問を10枚/日で回すと8年かかるため。`buildStudyQueue` の第4引数で受け、0 は無制限
  - 保存値の読み出しで `Number(null) === 0` が「無制限」と解釈される取り違えがあり、未設定を先に弾く形へ修正した（`loadNewCardsPerDay`）
- カード一覧の検索は 200ms のデバウンス付き。3391問デッキで1文字ごとに全走査すると重いため
- 1MB を超えるデッキ（quiz-koumin / quiz-rikei / quiz-seikatsu）は GitHub Contents API が本文を返さないので、アプリ内の「カード追加」「CSV取込」は使えない。これらは xlsx 側で管理して再生成する
- 生成の手順とカード id の規約は `decks/README.md`、変換スクリプトは `scripts/import-quiz-xlsx.py`

## デッキ一覧の検索・並び替えと出題順（2026-08-26 ユーザー要望）

- ホームに検索（デッキ名・説明）と並び替えを置いた。並び替えは**最近学習した順（既定）/ 名前順 / 学習できる枚数順 / 定着率順**で、選択は localStorage に覚える
- 「最近学習した」は**進捗レコードの `updatedAt` の最大値**を使う（`readProgress` は統計計算ですでに読んでいるので追加の読み込みは無い）。未学習デッキは末尾へまとめ、その中では名前順。デッキカードには最終学習日時も出す
- 絞り込みと並び替えは `src/decklist.ts` の純関数に置いてテストする。`snapshot.ts` 側の並び（名前順）は正本として変えない
- 学習開始シートに**出題順**を追加。「順番どおり」は従来どおり復習（期限が近い順）→ 新規（デッキの上から順）、「ランダム」は**枚数で切る前に**セッション全体をシャッフルする（数千問のデッキから無作為に選ぶため）
- **既定はランダム**（2026-08-26 ユーザー指定）。数千問のデッキでは順番どおりだと毎回デッキ先頭付近ばかり出るため。既定でなくなったので選択肢のラベルは「デフォルト」→「順番どおり」に改めた

## 学習リザルト（2026-08-26 ユーザー要望、Newmonic の画面を参考）

- **中断したとき**と**キューをやり切ったとき**の両方でリザルトを出す。中断はホームへ直行せず、いったんこの画面を挟む
- 達成率は**デッキ全体の積み上がり**を表す（2026-08-26 ユーザー指定で、セッション単体の正答率から変更）。計算は **定着（FSRS の state=Review）したカードのフェーズ合計 ÷ (デッキの枚数 × 10)**。満点は「フェーズ10かつ定着」（`achievementPercent`）
  - **定着していないカードは数えない**。reps は「もう一度」でも増えるため、reps だけで測ると*忘れ続けているカードほど達成率が上がる*（Codex レビューの指摘。実測でも「もう一度」10回のカードは reps=10・state=Learning になる）。実装前は「難しい」8回で 2.7% と出ていたが、修正後は 0.0% になることを確認した
  - セッション単体の手応えは、コメント欄の「今回のぶんで N フェーズ進みました」で伝える
  - 数千問のデッキでは1セッションで 0.0数%しか動かない。進みが見えるよう、**10%未満は小数第1位まで**表示する
- ゲージと数値は表示時に **0 から目標値までアニメーション**する（900ms・easeOutCubic、`requestAnimationFrame`）。アプリ内の「動きを減らす」設定（`data-motion="crossfade"`）では即座に確定させる
- ゲージは SVG の半円（`stroke-dasharray` で塗る）。淡いピンク `--color-gauge-start` からティールへのグラデーション
- 「つづける」は、中断なら**その場で学習に戻る**、やり切ったなら**同じ設定で新しいセッションを組み直す**。今日出せるカードが残っていない場合はボタンを出さず、その旨を書く
- **リザルトを表示している間は、早押しの読み上げタイマーを止める**。止めないと裏で問題が進み、戻ったときに読み上げが終わっている（2026-08-26 ユーザー報告）
- 中断から戻るときは、**中断していた時間を持ち込まない**ようにその問題を仕切り直す
  - 通常モード: 秒数評価の起点（`shownAt`）を戻った時点にリセットする。放置していた時間で「もう一度」判定になってしまうため
  - 早押し: **まだ押していなければ読み上げを最初からやり直す**（考える時間を余分に得た状態で続けさせない）。**押した後なら押した位置を保つ**（押した文字数はその問題の成績そのものなので消さない）
- 「今回めくったカード」に、評価ラベル・次回出題までの目安・問題文・答え・フェーズの推移（`0 › 1`）を新しい順で並べる
- **StudyView はセッションごとに `key` を変えて作り直す**。props だけ差し替えると `queue` や `result` の state が前のセッションのまま残り、「つづける」を押しても画面が変わらない（2026-08-26 に実際に発生）

## 学習カードの表示（2026-08-26 ユーザー要望）

- カード右上に**現在のフェーズ**（FSRS の reps）をチップで出す。新規カードでは「新規」チップと横に並べる
- カード本文の文字サイズを下げた（問題 24px → 20px、答え 22px → 19px、補足 15px → 14px）。長い問題文が多いデッキでは 24px だと画面に収まりきらないため

## Codex レビュー（2026-08-26）で入れた修正

本日の変更一式（`3ced9cc..afd7249`）を Codex に第三者レビューさせ、指摘のうち次を取り込んだ。

- **評価の排他を ref にした**。`handleRate` の入口は state の `saving` を見ていたが、state は再レンダーまで更新されないので同一フレームの多重入力を止められない。`ratingLockRef` で単一化し、対象カードもローカル変数へ固定した（保存中に `current` が差し替わっても取り違えない）。実測: 評価ボタン3連打でレビューログは1件、消費カードも1枚
- **`visibilitychange` で秒数評価の起点をリセット**する。アプリを離れていた時間が右スワイプの自動評価に混入し、戻って即答しても「もう一度」になっていた。早押しでまだ押していなければ読み上げもやり直す
- **保存中は「中断」を押せない**ようにした（保存結果が見えないまま画面を離れないため）
- **「つづける」の判定を作り直した**。`availableCount > reviewedCount` だと「もう一度」の再出題で `reviewedCount` が膨らみ、未出題のカードが残っていてもボタンが消えた。セッション後の進捗から `buildStudyQueue` を引き直して残数で判定する
- **`import-quiz-xlsx.py` は id 重複で停止する**。先勝ちで黙って捨てると、どちらの問題の進捗か分からなくなる。重複した行番号を並べて報告し、デッキファイルは書き換えない

取り込まなかった指摘: ズーム無効化（ユーザー指定の仕様）、キャッシュ判定の blob SHA 化（有効だが今回のスコープ外。`DeckCacheEntry` に `blobSha` を足して旧キャッシュを一度再取得すれば移行できる、と Codex も評価）

## スワイプの手触り（2026-08-26 実機フィードバック）

- 指を離して戻るときは `cubic-bezier(0.18, 1.25, 0.35, 1)` で 0.42 秒。行き過ぎてから収まるバネ風にしてカードらしい重みを出す（以前は 0.2 秒の ease で素っ気なかった）
- 追従中は回転を 0.04 → 0.06 deg/px に強め、横移動に比例して少し下へも動かす
- **閾値を超えたら、指の位置から画面外へ送り出してから評価を確定する**（`flyOut`、260ms）。`transitionend` には依存せず `setTimeout` で確定するので、既存の「アニメにロジックを載せない」方針は守る。評価のロックは飛ばし始めに取るため、飛行中の追加入力は無視される
- 「動きを減らす」設定では飛ばさず即座に確定する

## 敵対的検証（2026-08-26）

肯定的な動作確認だけでは足りないため、意図的に壊しにいく検証を行った。結果はいずれも期待どおり。

- **保存失敗**: `IDBObjectStore.prototype.put` を差し替えて cardProgress の書き込みを失敗させる → エラー表示・カードは消えない・**ログの二重書き込みなし**・復旧後に同じカードを再評価できる（ロックが解放されている）
- **オフライン**: 機内モード相当で再読込 → キャッシュから18デッキを表示、「オフライン: 〜時点のデータ」を表示し、学習も進む
- **極端なカード**: 1文字・400文字・ZWJ絵文字・空白のみの front を持つデッキをキャッシュへ注入 → 例外なし。ZWJ 絵文字の分解はこの検証で見つけ、`splitGraphemes` で修正した
- **連打**: 「つづける」6連打で画面は二重にならない。スワイプ確定と評価ボタン4クリックを同時に起こしてもレビューログは1件
