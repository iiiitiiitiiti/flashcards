# Design Decisions

UI に関する確定済みの設計判断。変更するときはここを更新する。

## ライトテーマ固定（2026-08-26 ユーザー決定）

- OS のダークモードには追従せず、常にライト配色で表示する（`color-scheme: light`、`prefers-color-scheme: dark` の上書きブロックは削除）
- `theme-color` メタタグも 1 枚（`#f6f6f4` = `--color-bg`）に統一。以前の light 用の値 `#f5f6f8` は背景色と一致していなかったので揃えた
- 配色トークン自体は据え置き。ダークを再開するなら `:root` のトークンだけを上書きする形に戻す

## ビジュアル言語（2026-08-10、Newmonic https://newmonic.baton8.com を参考に採用）

- ティール基調 + 温かみのあるオフホワイト背景（#f6f6f4）。プライマリは #2e7382（Newmonic の #489FB2 は白文字とのコントラスト 3.05 で不採用。当プロジェクトの 4.5:1 基準を満たす濃ティールに調整）
- **Q/A の色分け**: 一覧・学習画面とも「Q」=ティール、「A」=赤（#c53f35、ダークは #ef8b80）。答えは常に赤文字
- デッキ詳細の各カードに元順の番号とフェーズバッジ（= FSRS reps。定着（state=Review）は塗りつぶし）
- ホームのデッキカードに定着率ドーナツゲージ（定着カード数 / 全カード数、conic-gradient 製）
- セクション見出しはティール縦棒 + 太字。アプリタイトルはティール + letter-spacing 0.08em
- ボタン角丸 8px（Newmonic の角丸小さめの印象を反映しつつタップターゲット 44px は維持）
- 評価4択 + 間隔表示は維持（Newmonic は2択だが、SRS の判断材料として4択を優先する既決定）

- 学習画面の主要操作（答えを表示・4評価）は画面下部固定（HIG: Reachability。片手操作の親指ゾーンに置く）。カード本文は中央寄せ・24px/22px でコンテンツ優先（Deference）
- 評価ボタンには ts-fsrs の `repeat()` による次回間隔の目安（分/時間/日/か月/年）を常時表示する（評価の判断材料。Anki 互換の慣習）
- セッション進捗はヘッダー直下の進捗バーで表示。「もう一度」の再出題でバーが一時的に戻るのは仕様（正直な残量表示を優先）
- カラーは CSS 変数トークンで一元管理し、`prefers-color-scheme: dark` に対応。theme-color メタタグも light/dark の2枚で切替
- 全テキストはコントラスト比 4.5:1 以上を維持する（WCAG SC 1.4.3）。「難しい」ボタンは #b07a1f → #8a5f14 に変更済み（3.72→5.6）。値を変えるときは scratchpad の ui-audit スクリプト相当で実測してから
- ボタンは最小 44px 高（HIG タップターゲット）。学習画面の主要ボタンは 56px
- バッジ・タグはチップ表示（復習=赤系 / 新規=青系 / 完了=緑系。色+テキストの併用で色覚に依存しない）
- 状態切替（カードめくり）は state 即時反映、CSS transition は装飾のみ。`transitionend` にロジックを載せない（iOS「視差効果を減らす」対策）。`prefers-reduced-motion` では進捗バーの transition を無効化

## 学習画面の操作（2026-08-10 ユーザー指定）

- 学習中はページの上下スクロールを禁止する（body に study-lock クラス、overscroll-behavior: none）。カード本文が収まらない場合のみカード内部でスクロール
- カード枠は操作エリアを除く画面の縦いっぱいに広げる。中央寄せは auto マージン方式（justify-content: center は overflow 時に先頭が切れるため使わない）
- カードのタップは表⇄裏のトグル（答えを開いた後もタップで問題面に戻れる）
- カードの表裏は 3D 反転アニメーション（rotateY・0.4s）、次カードは右からの入場アニメーション（0.28s、key 再マウントで発火）。両面を常に DOM に置き backface-visibility で切替、非表示面は aria-hidden。状態切替は即時で、アニメはロジックに関与しない。**OS の `prefers-reduced-motion` は参照しない**（2026-08-10 ユーザー決定。Newmonic 等の一般アプリと同じく既定でフル再生）。動きを減らすのはアプリ内設定（設定画面 → アニメーション、`data-motion="crossfade"`）で、回転・移動をクロスフェードへ置き換える。zoo-aquarium-log の「既定は表示・設定でオフ」と同じ方針
- 学習カードは左右スワイプでも評価できる（左=もう一度、右=普通。答え表示中のみ有効）。「難しい」を左に割り当てないのは、FSRS では難しい(2)も合格扱いで間隔が延びるため「覚えてない」の意図とずれるから。難しい・簡単はボタン専用。スワイプ中はカードが指に追従し評価バッジ（次回間隔つき）を表示、閾値80px未満は復帰。縦スクロールとの競合は方向判定（縦優勢なら譲る）で回避

## 学習セッションの開始と評価（2026-08-26 ユーザー要望）

- ホームの「学習する」は即開始ではなく**開始シート**を挟む。モード（通常 / 早押し）と枚数（5・10・20・30）を選んでから始め、選択は localStorage に覚えて次回の既定にする
- 枚数は `buildStudyQueue` の結果（復習 → 新規の順）を先頭から切り取るセッション上限。1日の新規上限 `NEW_CARDS_PER_DAY` とは別の概念で、「もう一度」の再出題はこの上限に含めない
- 答え表示後の**ボタンは2つ**（「難しい」= Hard、「わかった」= Good）。4段階を全部ボタンに出すのはやめ、細かい振り分けはスワイプに寄せた
- **右スワイプは経過時間で自動評価**する。**問題が表示されてから**スワイプするまでが 5秒未満=簡単 / 10秒未満=普通 / 20秒未満=難しい / それ以上=もう一度（既定値。設定画面で変更でき、`normalizeRatingThresholds` が昇順・1〜600秒へ整える）。スワイプ中のバッジには判定結果と次回間隔を出す
- 計測の起点は**問題の表示**（2026-08-26 ユーザー訂正。当初は答えの表示を起点にしていた）。答えを見ている時間も込みで測るため、既定の境界は答え表示起点のとき想定していた 2/5/10 秒から 5/10/20 秒へ引き上げた。答えを表示したあと問題面に戻して見直しても起点は変わらない
- **左スワイプは「もう一度」固定**のまま。覚えていないと即断したときに秒数で揺れると困るため
- 判定境界は使いながら調整する前提の仮置き。閾値は `DEFAULT_RATING_THRESHOLDS` が正本

## 早押しクイズモード（2026-08-26 ユーザー要望）

- 問題文の1文字ずつ送りは**書記素単位**で切る（`splitGraphemes`）。`Array.from` だとサロゲートペアは割れないが ZWJ 絵文字（👨‍👩‍👧‍👦）や結合文字が分解される。`Intl.Segmenter` が無い環境ではコードポイント単位へフォールバック
- 問題文を1文字ずつ送り、**「押す」（またはタップ）で読み上げが止まるだけ**。答えは出さず、**もう一度タップ（または「答えを表示」）で答えを開く**（2026-08-26 ユーザー指定。押した直後に答えが出ると、思い出す時間が取れないため）。文字送りは `Array.from` で分割するのでサロゲートペアでも壊れない
- 速度は1文字あたり 速い70ms / 普通120ms / ゆっくり180ms。設定画面で選び、セッション開始時の値をそのセッション中は固定する
- 正誤は**自己申告**（「正解」= Good / 「不正解」= もう一度）。表記ゆれの誤判定を避けるためテキスト入力での自動判定は採らなかった
- 結果は通常学習と**同じ SRS 進捗に反映**する（進捗を2系統に分けない）。押した文字数はフッターに表示するだけで、評価には使わない
- 早押しでも**スワイプ評価を使える**（2026-08-26 ユーザー指摘で追加）。左=不正解 / 右=正解 で、ボタンと同じ2択に対応させる。通常学習と同じく答えを表示するまでスワイプは効かないので、読み上げ中に誤爆しない
- 早押しの経過秒数による自動評価はしない。速さは「何文字目で押したか」で表れるため、時間で測ると二重になる

## ピンチズームの無効化（2026-08-26 ユーザー指定）

- viewport メタに `maximum-scale=1.0, user-scalable=no` を付け、`body { touch-action: manipulation }` でダブルタップ拡大も止める
- iOS Safari は `user-scalable=no` を無視するため、`main.tsx` で `gesturestart` / `gesturechange` / `gestureend` を `preventDefault` して塞ぐ（WebKit 固有イベント）

## カード一覧・ヘッダー（2026-08-26 ユーザー要望）

- カード一覧は **30枚ごとのページネーション**。ページャは一覧の上下に置き、先頭・末尾・現在の前後を残して「…」で省略する（`buildPageItems`）。検索・タグを変えたら1ページ目へ戻し、ページ数が減ったら `clampPage` で範囲内へ収める
- `.app-header` は `position: sticky` で追従させる。`.app` の左右パディングぶん外へ広げて背景を全幅にする
- デッキ詳細・設定の戻るボタンは**左端の丸いアイコン**（○ の中に ←、44px）。テキストの「戻る」はやめた
- 設定のチェックボックスは横並び。縦積みになっていたのは `.settings-group label`（詳細度 0,1,1）が `.checkbox-label`（0,1,0）に勝っていたためで、`.settings-group .checkbox-label` を足して解消した

## 数万問のデッキへの対応（2026-08-26、クイズ.xlsx の29,781問を導入）

- 全問を1ファイルにすると 9.3MB になるため、**大ジャンル別の16デッキ**へ分けた（最大は quiz-seikatsu の 1.1MB / 3325問）。ジャンル別に学習でき、取得も分散する
- `refreshSnapshot` は**中身が変わったデッキだけ取り直す**。以前は毎起動で全デッキの raw を取り直していたので、10MB 級だと成立しなかった。実測: 初回 2.9秒 → 2回目 0.6秒・raw リクエスト0件
  - 判定は**ファイルごとの blob SHA**（ツリーAPI が返す `sha`）。最初はリポジトリの最新コミット SHA で見ていたが、それだとソースを1行直しただけでも全16デッキ（9.8MB）を取り直していた（2026-08-26、Codex レビューを受けて変更）
  - `commitSha` は raw URL の固定とスナップショットの整合性のために残す。キャッシュ再利用時も最新コミットへ更新する
  - `blobSha` を持たない旧キャッシュは一度だけ取り直す（`DeckCacheEntry.blobSha` は省略可）。削除・追加の判定は従来どおり一覧（`listing.decks`）を正とするので、リネームは新 id で取得され `validateDeck` で中身の id も検証される
- 1日の新規カード枚数を設定可能にした（10/20/50/100/無制限）。29,781問を10枚/日で回すと8年かかるため。`buildStudyQueue` の第4引数で受け、0 は無制限
  - 保存値の読み出しで `Number(null) === 0` が「無制限」と解釈される取り違えがあり、未設定を先に弾く形へ修正した（`loadNewCardsPerDay`）
- カード一覧の検索は 200ms のデバウンス付き。3391問デッキで1文字ごとに全走査すると重いため
- 1MB を超えるデッキ（quiz-koumin / quiz-rikei / quiz-seikatsu）は GitHub Contents API が本文を返さないので、アプリ内の「カード追加」「CSV取込」は使えない。これらは xlsx 側で管理して再生成する
- 生成の手順とカード id の規約は `decks/README.md`、変換スクリプトは `scripts/import-quiz-xlsx.py`

## デッキ一覧の検索・並び替えと出題順（2026-08-26 ユーザー要望）

- ホームに検索（デッキ名・説明）と並び替えを置いた。並び替えは**最近学習した順（既定）/ 名前順 / 学習できる枚数順 / 定着率順**で、選択は localStorage に覚える
- 「最近学習した」は**進捗レコードの `updatedAt` の最大値**を使う（`readProgress` は統計計算ですでに読んでいるので追加の読み込みは無い）。未学習デッキは末尾へまとめ、その中では名前順。デッキカードには最終学習日時も出す
- 絞り込みと並び替えは `src/decklist.ts` の純関数に置いてテストする。`snapshot.ts` 側の並び（名前順）は正本として変えない
- 学習開始シートに**出題順**を追加。「順番どおり」は従来どおり復習（期限が近い順）→ 新規（デッキの上から順）、「ランダム」は**枚数で切る前に**セッション全体をシャッフルする（数千問のデッキから無作為に選ぶため）
- **既定はランダム**（2026-08-26 ユーザー指定）。数千問のデッキでは順番どおりだと毎回デッキ先頭付近ばかり出るため。既定でなくなったので選択肢のラベルは「デフォルト」→「順番どおり」に改めた

## 学習リザルト（2026-08-26 ユーザー要望、Newmonic の画面を参考）

- **中断したとき**と**キューをやり切ったとき**の両方でリザルトを出す。中断はホームへ直行せず、いったんこの画面を挟む
- **定着率**は**デッキ全体の積み上がり**を表す（2026-08-26 ユーザー指定で、セッション単体の正答率から変更）。計算は **定着（FSRS の state=Review）したカードのフェーズ合計 ÷ (デッキの枚数 × 10)**。満点は「フェーズ10かつ定着」（`retentionPercent`）
  - 呼び名は当初「達成率」だったが、**2026-08-26 に「定着率」へ改めた**（Codex 指摘＋ユーザー決定）。この値は積み上げた総量ではなく「いま身についている割合」で、忘れて Relearning へ落ちたカードは 0 に戻る＝**値は下がりうる**。「達成」は積み上がりを連想させて実態と合わない
  - ホームのドーナツも**同じ `retentionPercent`** を使う。以前はドーナツだけ「state=Review のカードの枚数比」という別式で、同じ「定着率」の名で違う数字が出ていた
  - **定着していないカードは数えない**。reps は「もう一度」でも増えるため、reps だけで測ると*忘れ続けているカードほど定着率が上がる*（Codex レビューの指摘。実測でも「もう一度」10回のカードは reps=10・state=Learning になる）。実装前は「難しい」8回で 2.7% と出ていたが、修正後は 0.0% になることを確認した
  - セッション単体の手応えは、コメント欄の「今回のぶんで N フェーズ進みました」で伝える
  - 数千問のデッキでは1セッションで 0.0数%しか動かない。進みが見えるよう、**10%未満は小数第1位まで**表示する
- ゲージと数値は表示時に **0 から目標値までアニメーション**する（900ms・easeOutCubic、`requestAnimationFrame`）。アプリ内の「動きを減らす」設定（`data-motion="crossfade"`）では即座に確定させる
- ゲージは SVG の半円（`stroke-dasharray` で塗る）。淡いピンク `--color-gauge-start` からティールへのグラデーション
- 「つづける」は、中断なら**その場で学習に戻る**、やり切ったなら**同じ設定で新しいセッションを組み直す**。今日出せるカードが残っていない場合はボタンを出さず、その旨を書く
- **リザルトを表示している間は、早押しの読み上げタイマーを止める**。止めないと裏で問題が進み、戻ったときに読み上げが終わっている（2026-08-26 ユーザー報告）
- 中断から戻るときは、**中断していた時間を持ち込まない**ようにその問題を仕切り直す
  - 通常モード: 秒数評価の起点（`shownAt`）を戻った時点にリセットする。放置していた時間で「もう一度」判定になってしまうため
  - 早押し: **まだ押していなければ読み上げを最初からやり直す**（考える時間を余分に得た状態で続けさせない）。**押した後なら押した位置を保つ**（押した文字数はその問題の成績そのものなので消さない）
- 「今回めくったカード」に、評価ラベル・次回出題までの目安・問題文・答え・フェーズの推移（`0 › 1`）を新しい順で並べる
- **StudyView はセッションごとに `key` を変えて作り直す**。props だけ差し替えると `queue` や `result` の state が前のセッションのまま残り、「つづける」を押しても画面が変わらない（2026-08-26 に実際に発生）

## 学習カードの表示（2026-08-26 ユーザー要望）

- カード右上に**現在のフェーズ**（FSRS の reps）をチップで出す。新規カードでは「新規」チップと横に並べる
- カード本文の文字サイズを下げた（問題 24px → 20px、答え 22px → 19px、補足 15px → 14px）。長い問題文が多いデッキでは 24px だと画面に収まりきらないため

## Codex レビュー（2026-08-26）で入れた修正

本日の変更一式（`3ced9cc..afd7249`）を Codex に第三者レビューさせ、指摘のうち次を取り込んだ。

- **評価の排他を ref にした**。`handleRate` の入口は state の `saving` を見ていたが、state は再レンダーまで更新されないので同一フレームの多重入力を止められない。`ratingLockRef` で単一化し、対象カードもローカル変数へ固定した（保存中に `current` が差し替わっても取り違えない）。実測: 評価ボタン3連打でレビューログは1件、消費カードも1枚
- **`visibilitychange` で秒数評価の起点をリセット**する。アプリを離れていた時間が右スワイプの自動評価に混入し、戻って即答しても「もう一度」になっていた。早押しでまだ押していなければ読み上げもやり直す
- **保存中は「中断」を押せない**ようにした（保存結果が見えないまま画面を離れないため）
- **「つづける」の判定を作り直した**。`availableCount > reviewedCount` だと「もう一度」の再出題で `reviewedCount` が膨らみ、未出題のカードが残っていてもボタンが消えた。セッション後の進捗から `buildStudyQueue` を引き直して残数で判定する
- **`import-quiz-xlsx.py` は id 重複で停止する**。先勝ちで黙って捨てると、どちらの問題の進捗か分からなくなる。重複した行番号を並べて報告し、デッキファイルは書き換えない

取り込まなかった指摘: ズーム無効化（ユーザー指定の仕様）、キャッシュ判定の blob SHA 化（有効だが今回のスコープ外。`DeckCacheEntry` に `blobSha` を足して旧キャッシュを一度再取得すれば移行できる、と Codex も評価）

## スワイプの手触り（2026-08-26 実機フィードバック）

- 指を離して戻るときは `cubic-bezier(0.18, 1.25, 0.35, 1)` で 0.42 秒。行き過ぎてから収まるバネ風にしてカードらしい重みを出す（以前は 0.2 秒の ease で素っ気なかった）
- 追従中は回転を 0.04 → 0.06 deg/px に強め、横移動に比例して少し下へも動かす
- **閾値を超えたら、指の位置から画面外へ送り出す**（`flyOut`、260ms）。`transitionend` には依存しない
  - **保存は飛ばし始めと同時に開始する**。260ms 待ってから保存すると、その間にリロードや画面離脱が起きたとき評価が失われる（Codex 再レビューの指摘）
  - キューを進めるのは「保存の完了」と「飛び切り」の両方が揃ってから。先に進めるとカードが一瞬戻ってから消える
  - 飛行中にアンマウントされたらタイマーを clearTimeout し、以降の更新もしない（`mountedRef`）。保存はすでに始まっているので評価は残る
  - 評価のロックは飛ばし始めに取り、`handleRate` の `finally` で必ず解除する（`rate()` が例外を投げてもロックが残らない）
- 「動きを減らす」設定では飛ばさず即座に確定する

## Codex 再レビュー（2026-08-26、2回目）で入れた修正

1回目の修正後にもう一度レビューさせたところ、**私が直前に入れた `flyOut` が新しいリスクを作っていた**と指摘された。

- **保存を飛行開始と同時に前倒し**した（上記）。260ms の遅延中に画面を離れると評価が失われる経路があった

## 保存容量まわり（2026-08-26、Codex 指摘の積み残しを解消）

デッキだけで約 9.7MB あり、進捗と評価ログが上に乗る。容量不足は「いつか起きること」として扱う。

### 評価ログの間引き（`pruneReviewLog`）

- `reviewLog` は**出題の判断には使っていない**（予定は `cardProgress` が持つ）。バックアップに残す履歴なので、古いものは消してよい
- **400日**より古いログ、それでも **20,000件**を超えるぶんを古い順に削除する。起動時に一度だけ実行し、失敗しても学習は続ける（握りつぶす）
- 日時で引けるように `reviewLog` へ `byReviewedAt` インデックスを足し、**DB を v1 → v2 へ引き上げた**。`upgrade` は `oldVersion` で分岐し、v1 で作られた既存 DB にはインデックスだけを後付けする（データは消さない）
  - 既存データを持つ v1 の DB から引き上げても進捗・ログが残ることを、fake-indexeddb のテストと**実ブラウザの既存 DB**（localhost:4173、9.7MB のキャッシュ入り）の両方で確認した

### 容量不足の扱い（`src/quota.ts`）

- `QuotaExceededError` / `NS_ERROR_DOM_QUOTA_REACHED` を `isQuotaExceeded` で見分ける。名前はブラウザで違うので `name` で判定する
- 容量不足は「もう一度お試しください」では直らない。`describeStorageError` が**そのときだけ別の文言**（設定の「保存容量」を見る・不要な進捗を消す）を返す。学習中の保存失敗・バックアップ取り込みの両方で使う
- **デッキキャッシュの保存に失敗しても起動は続ける**。取得済みのデッキをそのセッションで使い、警告だけ出す（以前は例外がそのまま上がっていた）
- 設定画面に **保存容量（使用量 / 上限）** を出す。`navigator.storage.estimate()`。永続化の表示と並べて、容量不足の案内から辿れるようにした
- 永続化の要求は `requestPersistentStorage()` に寄せ、**すでに永続なら再要求しない**

### バックアップ書き出しのメモリ（`exportBackup`）

- 以前は `getAll` で全件を配列に読み、それを `JSON.stringify` していた。進捗3万件規模では**オブジェクト配列とその JSON 文字列を同時に抱える**
- カーソルで1件ずつ `JSON.stringify` し、断片の配列を `Blob` へ渡す形に変えた。返り値は `{ blob, exportedAt, progressCount, logCount }`
- `URL.revokeObjectURL` は `click()` の直後ではなく**60秒後**にする。直後に revoke すると保存が始まる前に無効になる端末がある

## タグで絞って学習（2026-08-26 ユーザー要望）

タグ（サブジャンル・難易度・「出題済み」）は全カードに入っていてカード一覧（`DeckDetailView`）では絞り込めるのに、**学習セッションには効いていなかった**。2,584問のスポーツから「相撲だけ」を回せるようにする。

- 学習開始シートに**タグの `<select>`** を置く。タグを持つカードが1枚も無いデッキでは出さない（カード一覧の絞り込みと同じ判定）
- 絞り込みは `buildStudyQueue` の第5引数 `tag`。**復習キューと新規キューの両方**に効く。`null` と `""` は「全タグ」（select の未選択が `""` で来る）
- **新規カードの1日上限はデッキ単位のまま数える**。タグごとに枠を数えると、タグを切り替えるだけで上限が実質無限になる。実測: 上限3・今日2枚導入済みのデッキで「難易度A」に絞ると、新規は1枚しか出ない
- 選んだタグは **デッキごとに** localStorage へ覚える（キー `flashcards:study-tag:<deckId>`）。タグの体系はデッキごとに違うので、1つを共有すると別デッキで0枚になる
  - デッキが更新されてそのタグが消えた場合は、開くときに**「全タグ」へフォールバック**する（`openStartSheet` がデッキのタグ一覧と突き合わせる）
- シートに**そのタグでいま学習できる枚数**（復習 N・新規 N）を出し、**0枚なら「開始」を押せなくする**。数千問のデッキでは、絞った結果が空かどうかが開始前に分からないため
- **定着率の母数はデッキ全体のまま**。ゲージはデッキの定着率であり、ホームのドーナツと同じ数字でなければならない（タグで絞ると母数が変わって別物になる）
- 完走時の「今日出せるカードは終わりました」は、タグ絞り込み中は**タグ名で書く**（`「生活」で今日出せるカードは終わりました。`）。デッキにはまだ他タグのカードが残っているので、「このデッキで」は事実と違う

### 動作確認（preview + Playwright）

- 「生活」で開始 → 出題された4枚が `生活` タグの4枚と**完全一致**（他タグの混入なし）
- 「地理」で枚数5・完走 → **「つづける」で次のセッションも地理のまま**、10枚すべて地理タグ・重複なし
- 枚数表示: 全タグ「復習1・新規9」→ 地理「復習0・新規9」（日次残枠で頭打ち）→ 生活「復習0・新規4」（タグの総数が枠より少ない）
- 生活を出し切ったあと再度開くと**タグが復元され**、「復習0・新規0」で**開始が無効**
- 存在しないタグを localStorage へ入れて開く → 全タグへフォールバック
- タグを持たないデッキをキャッシュへ注入 → select は出ず、記憶に残っていた別デッキのタグでも絞られない

## `npm run decks:sync`（2026-08-26）

Excel を直したあとのデッキ更新は手で3ステップ（生成 → validate → commit）で、**差分を見ないまま push できてしまう**のが問題だった。
`scripts/sync-decks.mjs` に一本化する。

1. `decks/` に未コミットの変更があれば止める（生成した差分と混ざるため）
2. **比べる相手（HEAD の内容）を先に読む** → `import-quiz-xlsx.py` → `validate-decks.mjs`
3. デッキ別に 追加 / 削除 / 変更 の件数を表示
4. **カード id が消えていたら一覧（最大20件）を出して exit 1**。`--allow-removals` で続行
5. 問題なければ `git add -- decks` → commit → push（`--dry-run` で止められる）

- `git show` は**デッキ1ファイルで最大2.6MB** あり、`spawnSync` の既定 `maxBuffer`（1MB）では ENOBUFS で落ちる。256MB を指定している
- `git add -- decks` に限定しているので、無関係な変更は巻き込まない（使い捨てリポジトリで確認済み）

### 動作確認

- 実データで再生成 → **「変更はありません」**（生成が冪等であることの確認も兼ねる）
- 小さなテスト xlsx（既存 id の問題文を差し替え1件＋新 id 2件）で実行 → `quiz-rikei 追加1 / 削除3366 / 変更1`、`quiz-chiri 追加1 / 削除2988` を検出し、**削除ありで exit 1**
- `--allow-removals` で続行、`--dry-run` で commit しないことを確認
- `decks/` を汚した状態・xlsx が存在しないパスで、それぞれ exit 1
- commit / push のコマンド列は使い捨てリポジトリで検証（複数行のコミットメッセージ、無関係ファイルを巻き込まないこと）

## カードのメモ・非表示・早押しの再開（2026-08-26 ユーザー要望）

### メモ（`cardNotes`）

- デッキ JSON の `note`（xlsx 由来の補足）とは**別物**として持つ。デッキは再生成で上書きされるうえ、1MB を超えるデッキはアプリから書き戻せない
- 保存先は IndexedDB の `cardNotes`（key `[deckId, cardId]`）。**進捗と同じくこの端末にしか無い**ので、バックアップにも含める
- **ヘッダーではなく、ヘッダーの下・カードの上に右寄せ**で置く（2026-08-26 ユーザー指定）。ヘッダーはタイトルと戻るだけにする
- **とじるときに保存**し、空にしたらレコードごと削除する（空のメモを持ち歩かない）
- メモがあるカードはアイコンを塗り（`--color-primary` + 白抜き）にして、書いてあることが分かるようにする
- 答えの下に、出典の補足とは色を変えて出す。改行は `white-space: pre-wrap` で残す

### 非表示（`hiddenCards`）

- 時事ネタが古くなるなど、**カードを消さずに出題から外したい**とき用。学習進捗は消さないので、戻せば続きから再開できる
- 除外は `buildStudyQueue` に引数を足さず、**App 側で `visibleDeck()`（非表示を抜いたデッキ）を作って渡す**。こうすると出題キューと**定着率の母数**が自動的に揃う（「もう出さない」カードを分母に残すと 100% にできない）
- カード一覧では通常の一覧から外し、**`<details>` の「非表示のカード（N）」**へまとめる。既定は畳んでおく
- 学習中に非表示にすると、**評価せずにキューから抜く**（「もう一度」の再出題にも乗せない）
- 取り込み時の扱い: メモは `updatedAt` が新しい方を採用、非表示は**追記のみ**（別端末での解除は持ち込まない。消したつもりの非表示が復活するより、余分に非表示が残る方が実害が小さい）

- 設定タブからは**戻る矢印を外した**（タブに戻るボタンがあるのは筋が悪い）。タブを離れるときに `refresh()` を呼んで、変えた設定を反映する
- `.app-with-nav` で本文の下を 76px 空ける。**ダイアログの `z-index` を 20 → 30 へ上げた**。同値だと後から描かれるナビが学習開始シートの「開始」ボタンを覆い、実際に押せなくなっていた（Playwright の「nav-tab intercepts pointer events」で発覚）

### 統計

集計は `src/stats.ts` の純関数に閉じ込め、画面は `StatsView.tsx` が読むだけにした。

- **プレイ時間はこれまでどこにも記録がなかった**ため、`reviewLog` に `elapsedMs`（問題表示から評価までの時間）を足した。古いログには無いので**省略可**にし、集計では 0 として扱う
  - **1枚あたり5分で頭打ち**にする。席を外したぶんまで足すと「プレイ時間」が実態と合わない
  - 0分と出るのは寂しいので、**1分未満でも学習していれば 1 分**として表示する
- カレンダーは**日曜始まりの7列**。曜日と月末は `Date.UTC` で数える（端末のタイムゾーンで曜日がずれると、Asia/Tokyo 固定の `dayKey` と食い違う）
- **学習した日に点**を打つ（添付には無いが、どの日に学習したかが一目で分かる）
- **未来の月へは進めない**（次月ボタンを disabled にする）
- 「暗記済みデッキ」は**非表示のカードを除いた枚数**で判定する（出題されないカードを分母に残すと、いつまでも達成できない）
- 「プレイしたデッキ」は**ログにしか出てこないデッキも数える**（デッキが消えても、学習した事実は残る）

### 動作確認（preview + Playwright、390×844）

- ボタン高 39px・14px、下ナビ3タブ（各56px）、現在タブに `aria-current`、ヘッダーから「設定」が消えた
- 統計: カレンダー42マス・31日・選択は今日・学習した日に点1つ・次月ボタンは disabled
- **7秒待ってから評価すると `elapsedMs: 8s` が記録され**、統計のプレイ時間が 0 → 1 分になった
- 学習していない日（8/10）を選ぶと日別がすべて 0、前の月（2026/07・31日）へ移ると次月ボタンが有効に戻る
- 学習中とカード一覧では下ナビが出ない。設定タブは戻る矢印なし、最下部の要素（768px）がナビ（787px〜）に隠れない。横スクロールなし

## 直前の評価を取り消す（2026-08-27 ユーザー要望）

逆向きにスワイプしてしまったときの復旧用。ボタンは**メモ・非表示と同じ行の左端**（役割が違うので離す）。

- 取り消しで戻すのは **進捗・評価ログ・キュー・セッションの記録**の4つ。`undoReview` が進捗とログを**同一トランザクション**で戻し、画面側がキューと `sessionLog`・`reviewedCount` を戻す
- **初回評価だったカードは進捗レコードごと削除する**（「評価前」の状態がレコード無しなので、0 に上書きするのではなく消す）
- **「もう一度」で末尾へ足した再出題を先に取り除く**。これを忘れると同じカードがキューに2枚残る
- 控えはセッション内に**スタックで持つ**ので、押すたびに1つずつ戻れる。セッションを離れると消える（`key={sessionId}` で作り直されるため）
- 戻したカードは**答えを出したまま**にする。付け直すのが目的で、読み直させる必要はない
- **経過時間を引き継ぐ**（`Date.now() - 取り消し前の elapsedMs` を `shownAt` に入れる）。計測をやり直すと、戻した直後に右スワイプしただけで「簡単」へ倒れてしまう
  - カード切り替えの効果（`[current, reviewedCount]`）が `shownAt` を上書きするため、引き継ぎ値は ref 経由でその効果に渡す
- **リザルト画面にも「直前の評価を取り消す」を置いた**。最後の1枚を誤ってスワイプするとリザルトへ移ってしまい、カード上のボタンでは戻せない。要望の配置（カードの上・左端）はそのままに、行き止まりだけ塞いだ

### トランザクションの取り扱い（検証で見つけた不具合）

最初の実装は `await progress.put()` のあとに `await log.delete()` と書いていた。**間で待つと、片方だけ済んだところでトランザクションが確定する**。
ログ削除だけを失敗させる注入試験で、**進捗だけ巻き戻ってログが残る**半端な状態を実際に作れた（progress 5→4 / logs 5 のまま）。

- 2つの要求を **await を挟まずに出して** `Promise.all` で待つ
- 失敗したら `tx.abort()` で巻き戻す
- 中断で残りの要求が `AbortError` になっても**未処理の rejection にしない**（`request.catch()` と `tx.done.catch()`）
- リザルト画面にはエラー表示が無かったので追加した（失敗しても気づけなかった）

### 動作確認（preview + Playwright、390×844）

- ボタンは left=16（左端）、メモ・非表示は右端（338〜374）。取り消せるものが無い間は無効
- 「難しい」で評価 → 次のカードへ（残り5→4、progress 1件・log 1件）→ 取り消し → **元のカードへ戻り、答えが出たまま、残り5枚、DB は空**（新規カードなので進捗ごと削除）
- **左スワイプ（もう一度）を取り消す**と、末尾へ足した再出題も消えて枚数が合う（5枚のまま）
- 2回評価 → 2回取り消しで、逆順にカードが戻り DB も 3件→2件→1件
- **72秒放置して右スワイプ（もう一度）→ 取り消し → すぐ右スワイプでも 73秒扱い**（引き継がなければ約1秒＝「簡単」になっていた）
- 取り消しボタンの**3連打で消えるのは1件だけ**（ロックが効いている）
- 5枚やり切ってリザルト → **「直前の評価を取り消す」で最後のカードへ戻る**（DB 5件→4件、残り1枚）
- ログ削除を失敗させると **DB は一切変わらず**、「評価の取り消しを保存できませんでした」を表示。復旧後に押し直すと成功。page error は0件

## 2026-08-27: タップしたときの押下表現

下ナビやボタンをタップすると一瞬黒くなるのは、CSS ではなく **OS 既定のタップハイライト**（`-webkit-tap-highlight-color`）だった。
`*` で透明にして消し、代わりに `button:active:not(:disabled)` で `scale(0.96)` ＋ `opacity: 0.72`（0.12s）を当てる。

- 押した見た目は `:hover` ではなく **`:active` で作る**。iOS では `:hover` がタップ後に居座るため
- 無効なボタンは沈まない（`:not(:disabled)`）
- 動きを減らす設定（`data-motion="crossfade"`）では沈まず、薄くなるだけ。**同じ詳細度なので基本ルールより後ろに置く**
- `.flip-scene` は `<div>` なので、めくり・スワイプのアニメーションとは衝突しない

却下案と検証結果は `docs/decisions/003_press-feedback-tap-highlight.md`。

## 2026-08-27（訂正）: Codex レビューと敵対的検証で見つかった3件

### 1. IndexedDB の真因を取り違えていた

「要求と要求の間で `await` するとトランザクションが自動確定する」と書いたが、**誤り**。素の IndexedDB で測った結果：

- `await put(a); await put(b);` → **両方コミットされる**
- 間に `setTimeout` を挟むと `InvalidStateError`（**IDB 以外を待ったときだけ**確定する）
- **成功した要求のあとに例外が抜けると、その要求はコミットされる** ← 注入試験で踏んだのはこれ

真因は「例外が抜けてもトランザクションは中止されない」こと。効いていたのは `abort()` の方だった。
同じ穴が **`saveReview` に残っていた**（毎回の評価が通る主経路）。両方を `runAtomically` に通し、
`tx.done` を最初に掴む・要求を作った端から登録する・失敗したら `abort` して `allSettled` で後始末、へ統一。
詳細は `docs/decisions/002`。

### 2. 押下表現は iOS で成立していなかった

**iOS Safari はタップで `:active` を当てない。** タップハイライトを消したうえで `:active` だけに頼ると、
iPhone では押した手応えが完全に消える。`main.tsx` で `pointerdown` → `data-pressed` を付け外しし、
CSS は `:active` と `[data-pressed]` の両方に当てる。`<summary>` も対象に含めた。
解除に `pointerout` は使わない（子の `svg` へ移っただけで飛ぶ）。詳細は `docs/decisions/003`。

### 3. 保存中に画面を離せてしまった

取り消しの書き込み中でもリザルトの「つづける」「終了する」、カードのメモ・非表示が押せた。
書き込み前の DB を新しいセッションが読む経路になるため、`saving` の間は無効化する。

## 2026-08-27: デッキ一覧の「更新」をアイコンにする
